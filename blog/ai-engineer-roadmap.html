The AI Engineer Roadmap

Free GitHub repos, YouTube playlists and a step-by-step plan to become an AI Engineer in India.

AI EngineeringRoadmap
Nikhil Kumar Tiwary 10 Nov 2026 10 min read
See the plan Download PDF
The truth firstAn AI Engineer is a backend developer who knows AI. You will spend less time training models and more time on data, APIs, cost, speed and accuracy. This roadmap is built for that job.

All links were checked in November 2026. Every resource here is free.

How to use this roadmap

  • Go in order. Each phase uses the one before it.
  • Pick one resource per topic and finish it. Collecting links is not learning.
  • Build the project at the end of every phase and push it to GitHub. Projects get you interviews, not certificates.
  • Spend 1 to 2 hours a day. Total time is about 5 to 6 months.
  • Stuck for more than 30 minutes? Ask AI to explain, then write the code yourself.

Phase 01: Python and Git 3 to 4 weeks

Everything else is built on this. You do not need to be an expert. You need to be comfortable.

What to learn

  • Variables, loops, functions, lists, dicts
  • OOP basics: classes and objects
  • Files, JSON, error handling (try / except)
  • Virtual environments and pip
  • Git basics: commit, branch, push, pull request

Phase 02: Data handling 2 to 3 weeks

AI can help you clean data. But understanding the data is your job. Bad data in, bad answers out.

What to learn

  • NumPy and pandas basics
  • Cleaning: missing values, duplicates, wrong formats
  • Reading CSV, JSON, PDFs and text files
  • SQL basics: SELECT, JOIN, GROUP BY

Phase 03: Backend with FastAPI 4 to 5 weeks

This is the 40% nobody tells you about. An AI engineer is a backend developer who knows AI.

What to learn

  • How REST APIs work: GET, POST, status codes
  • FastAPI + Pydantic for request and response models
  • PostgreSQL with SQLAlchemy, migrations with Alembic
  • Auth (JWT), testing with pytest
  • Docker basics, async in Python
  • Basic system design: caching, queues, rate limits

Phase 04: LLM basics, APIs and prompting 2 to 3 weeks

You will call models through APIs every day. Learn how they work and how to talk to them.

What to learn

  • What tokens, context window and temperature mean
  • Calling OpenAI, Claude and Gemini APIs from Python
  • Prompt engineering: clear instructions, examples, roles
  • Structured output (JSON) and function / tool calling
  • Streaming responses

Phase 05: RAG (chat with your data) 3 weeks

Most company AI products are RAG. The model answers using your documents, not only its memory.

What to learn

  • Embeddings and vector databases (Pinecone, Qdrant, pgvector)
  • Chunking documents the right way
  • Retrieval, re-ranking, hybrid search
  • Checking if answers are grounded in the documents

Phase 06: Agents and MCP 3 weeks

Agents let the model use tools: search, databases, APIs. MCP is the standard way to plug tools in.

What to learn

  • Tool calling and the agent loop
  • LangGraph: state, nodes, memory, human-in-the-loop
  • MCP: build a simple MCP server and connect it
  • When NOT to use an agent (simple code is often better)

Phase 07: Production: cost, speed, accuracy 3 weeks

This is what you do at the job. A demo works once. A product works 10,000 times a day.

What to learn

  • Latency: streaming, smaller models, parallel calls
  • Cost: model routing (cheap model for easy tasks), token limits
  • Caching repeated questions
  • Retries, timeouts and a backup model when the API fails
  • Handling bad JSON from the model
  • Evals: test sets, LLM-as-judge, error analysis
  • Logging and tracing every call

The production checklist

Run every AI project through these questions. This is what interviewers and real teams ask.

ProblemWhat you do
A call takes 8 seconds?Stream the answer, use a smaller model, run calls in parallel.
API bill keeps growing?Cheap model for easy tasks, big model only for hard ones. Cut extra tokens.
Same question comes again and again?Cache it. Do not pay twice.
Model wrote a story instead of JSON?Use structured output, validate with Pydantic, retry on failure.
API is down or rate limited?Retries with backoff, timeouts and a backup model.
Model is confidently wrong?Build an eval set, measure accuracy, read the failures yourself.
Something broke in production?Log every prompt, response, latency and cost so you can trace it.

Optional: want to train models? That is the ML Engineer path

Model training and research is a different role. In India these jobs are few and many need an MS or PhD. If this excites you, do it after Phase 4, alongside the rest.
